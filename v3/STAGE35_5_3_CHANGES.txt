230MATCH V3 Stage35.5.3 — 로컬 우선·Firebase 부하 보호

기준본
- Stage35.5.0을 기준으로 작업
- Stage35.5.1 및 Stage35.5.2 부서별 동기화/접속자 표시 업데이트는 보류

핵심 원칙
1. 시합 운영은 브라우저 로컬 상태가 우선이다.
2. Firebase 장애·과부하·인터넷 단절이 경기 진행을 막아서는 안 된다.
3. Firebase는 실시간 운영의 단일 실패 지점이 아니라 보조 동기화·백업 수단이다.
4. 서버 오류 중에도 결과 입력, 코트 이동, 대기열, 문자 대상 생성은 계속 작동한다.

변경 사항
- 연속 변경을 2.5초 동안 합쳐 최신 상태 1건만 Firebase에 저장
- Firebase 자동 쓰기 최소 간격을 6초로 제한
- 같은 상태 중복 저장 생략 유지
- 오프라인에서는 Firebase 재시도를 멈추고 로컬 저장만 수행
- resource-exhausted 또는 연속 4회 오류 시 2분간 서버 보호 회로 작동
- 보호 회로 중 반복 재시도 금지, 최신 상태 1건만 대기
- 2분 후 최신 상태 1건으로 자동 재동기화
- 수동 현재 상태 업로드/클라우드 불러오기 기능 유지
- 기존 revision 충돌 방지 유지
- 접속자 presence 쓰기 기능은 추가하지 않음

시합 당일 운영 주의
- 여러 진행자가 같은 대회방을 동시에 편집하면 각 기기에서 Firebase 읽기/쓰기가 발생한다.
- 동시 접속자가 많을수록 Firestore 사용량, 트랜잭션 충돌, 네트워크 지연 가능성이 증가한다.
- 진행자 계정은 꼭 필요한 인원만 사용하고, 관람·조회 사용자는 쓰기 권한을 주지 않는다.
- Firebase 오류 표시가 나와도 로컬 운영은 계속하며, 네트워크가 안정된 뒤 수동 업로드 또는 자동 재동기화를 확인한다.
- 대회 종료 전 전체 JSON 백업을 한 번 내려받는다.
